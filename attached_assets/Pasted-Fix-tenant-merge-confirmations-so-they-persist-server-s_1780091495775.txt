Fix tenant merge confirmations so they persist server-side and actually "stick" across sessions/devices.

ROOT CAUSE: The server already applies aliases on read — GET /deals runs enrichTenants() which stamps canonicalName on every tenant from the tenant_aliases table, and the Tenant Audit groups by canonicalName. But the confirm/merge flow in the frontend only writes to localStorage/IndexedDB, never to the server. So the alias table never learns, and the same splits keep reappearing. Fix the three gaps below.

────────────────────────────────────────
PART 1 — Write confirmed merges to the server
File: artifacts/om-database/src/lib/utils.ts

In addUserMerge(), after the existing local saves (localStorage + saveTenantDecision), POST the variants to the alias table:

  const entries = merge.variants.map(v => ({
    rawName: v,
    canonicalName: merge.canonical,
    notes: "user-confirmed-merge",
  }));
  fetch("/api/aliases", {
    method: "POST",
    credentials: "include",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(entries),
  }).catch(() => { /* non-fatal: local save already succeeded */ });

────────────────────────────────────────
PART 2 — Add a DELETE endpoint so "undo/restore" removes the server alias
File: artifacts/api-server/src/routes/aliases.ts

Add an authenticated route:

  // DELETE /api/aliases/:rawName — remove a single alias mapping
  router.delete("/aliases/:rawName", requireAuth, async (req, res) => {
    try {
      const rawName = decodeURIComponent(req.params.rawName);
      await db.delete(tenantAliasesTable).where(eq(tenantAliasesTable.rawName, rawName));
      res.json({ ok: true });
    } catch (err) {
      req.log.error({ err }, "Failed to delete tenant alias");
      res.status(500).json({ error: "Failed to delete tenant alias" });
    }
  });

(Add `import { eq } from "drizzle-orm";` at the top if not already present.)

Then in artifacts/om-database/src/lib/utils.ts, in removeUserMerge(), after the existing local removal, delete each variant's alias from the server:

  const m = _userMerges.find(x => x.id === id); // capture BEFORE removing, reorder if needed
  // ...existing removal logic...
  if (m) {
    for (const v of m.variants) {
      fetch(`/api/aliases/${encodeURIComponent(v)}`, { method: "DELETE", credentials: "include" }).catch(() => {});
    }
  }
Make sure you read the variants off the merge object BEFORE it's filtered out of _userMerges.

────────────────────────────────────────
PART 3 — Reload deals after a confirm so the merge shows immediately
File: artifacts/om-database/src/components/TenantAudit.tsx (and its parent if needed)

After a successful merge() confirmation, trigger a reload of deals from the server so the freshly-applied canonicalName flows in and the pair collapses without a manual page refresh. Use whatever deals-refresh mechanism the app already has (e.g. the same apiLoadDeals path App.tsx uses on mount). If TenantAudit doesn't already receive a refresh callback, add an optional onDealsChanged prop and call it after merge() and after restoreMerge(). Wire it in the parent to re-fetch deals.

────────────────────────────────────────
DO NOT change the dismissal ("keep separate") flow — that's a UI-only suppression and stays local for now.
